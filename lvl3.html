LVL 3 · Station 1 · Grundlagen

Die drei Grundbausteine eines Servers

⚙ Tools – Aktoren

Funktionen, die etwas tun oder berechnen: SQL-Abfrage ausführen, Datei anlegen, Mail senden.

gesteuert vom Modell: Das LLM entscheidet, wann es ein Tool braucht.

tools/list · tools/call

▤ Resources – Speicher

Daten zum Lesen, jeweils mit einer Adresse (URI): Dateiinhalt, Datenbankschema, Dokumentation.

gesteuert von der Anwendung: Der Host bzw. der Mensch wählt aus, was als Kontext mitgegeben wird.

resources/list · resources/read

☰ Prompts – Befehlssätze

Vorgefertigte Vorlagen für typische Aufgaben, oft mit Platzhaltern, z. B. „Notenbericht für Klasse ___“.

gesteuert vom Menschen: Er wählt die Vorlage bewusst aus, etwa als Slash-Befehl.

prompts/list · prompts/get

LVL 3 · Station 2 · Grundlagen

Tools entdecken: tools/list

Der Client fragt: „Was kannst du?“ Der Server antwortet mit einer Liste. Jedes Tool hat einen Namen, eine Beschreibung (die liest das LLM!) und ein inputSchema. Das ist ein JSON Schema, das festlegt, welche Parameter erwartet werden.

{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "tools": [
      {
        "name": "query_database",
        "description": "Führt eine SQL SELECT-Abfrage auf der Schul-Datenbank aus.",
        "inputSchema": {
          "type": "object",
          "properties": {
            "query": { "type": "string", "description": "Die SQL SELECT-Abfrage" }
          },
          "required": ["query"]
        }
      }
    ]
  }
}
LVL 3 · Station 3 · Grundlagen

Tools benutzen: tools/call

Anfrage

{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "query_database",
    "arguments": {
      "query": "SELECT vorname, klasse FROM schueler LIMIT 2"
    }
  }
}

Antwort

{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "[{\"vorname\": \"Anna\", \"klasse\": \"5a\"}, {\"vorname\": \"Leon\", \"klasse\": \"5a\"}]"
      }
    ],
    "isError": false
  }
}

Das Ergebnis steckt in result.content, einer Liste von Inhalten. Neben "text" gibt es z. B. auch "image" oder "audio".

LVL 3 · Station 5 · Erweiterung

Benachrichtigungen & Gegenrichtung

  • Änderungen melden: Wenn sich die Werkzeugliste ändert, schickt der Server die Notification notifications/tools/list_changed. Der Client fragt dann erneut tools/list ab.
  • Fortschritt: Bei langen Aufgaben kann der Server notifications/progress senden.
  • Abbrechen: Mit notifications/cancelled kann eine laufende Anfrage abgebrochen werden.

Auch der Client kann dem Server Fähigkeiten anbieten, wenn er sie beim Handshake ankündigt:

SamplingDer Server bittet den Host, das LLM etwas formulieren zu lassen. Der Server braucht dann kein eigenes Modell.
RootsDer Host teilt mit, in welchen Ordnern der Server arbeiten darf.
ElicitationDer Server fragt beim Menschen nach einer fehlenden Angabe, z. B. „Für welche Klasse?“
LVL 3 · Station 6 · Erweiterung

MCP Apps: Das Modul bringt seinen eigenen Bildschirm mit

Bisher liefert ein Tool immer Text, meistens JSON. Das LLM formuliert daraus eine Antwort. Das funktioniert, hat aber Grenzen:

  • Eine Notenübersicht mit 17 Schülerinnen und Schülern ist als Text unübersichtlich.
  • Willst du eine andere Klasse sehen, musst du wieder fragen, und das LLM muss wieder ein Tool aufrufen.
  • Bei einer Freigabe siehst du nur schueler_id: 37, kurs_id: 12. Wer ist das?

MCP Apps lösen das. Seit Januar 2026 sind sie die erste offizielle Erweiterung von MCP, gemeinsam entwickelt von Anthropic und OpenAI. Ein Server kann damit zu einem Tool eine HTML-Seite mitliefern, die der Host direkt im Chat anzeigt.

Die zwei Teile einer MCP-App

▤ UI-Ressource

eine HTML-Seite, die der Server als Resource mit einer Adresse ui://… anbietet. Der MIME-Typ text/html;profile=mcp-app sagt dem Host: Das ist eine App-Oberfläche.

{
  "uri": "ui://schule/notenuebersicht.html",
  "name": "notenuebersicht",
  "mimeType": "text/html;profile=mcp-app"
}

⚙ Tool mit Verweis

ein ganz normales Tool, das im Feld _meta.ui.resourceUri auf diese Seite zeigt.

{
  "name": "notenuebersicht",
  "description": "Zeigt die Noten einer Klasse …",
  "inputSchema": { … },
  "_meta": {
    "ui": { "resourceUri": "ui://schule/notenuebersicht.html" }
  }
}

Der Rest ist ganz normales MCP: Das Tool gibt Daten zurück, und das LLM sieht diese Daten wie immer. Neu ist, dass der Host die Seite mit resources/read holt, sie in einem abgeschotteten Rahmen (Sandbox) anzeigt und ihr das Tool-Ergebnis übergibt. App und Host sprechen dabei wieder JSON-RPC, nur eben innerhalb des Browsers per postMessage.

Ausprobieren: eine App im Chat

Jemand hat gefragt: „Zeig mir die Mathe-Noten der 7a.“ Wechsle in der App Klasse und Fach und beobachte rechts, wer mit wem spricht. Achte besonders auf die Anzeige LLM.

🖥 HOST · ChatLLM unbeteiligt
Zeig mir die Mathe-Noten der 7a.
🧠 ruft notenuebersicht auf: {"klasse": "7a", "fach": "Mathematik"}
▣ App · ui://schule/notenuebersicht.htmlSandbox

LLM-Aufrufe: 0 · Tool-Aufrufe aus der App: 0

Die zentrale Erkenntnis: Die App kann selbst Tools aufrufen. Klickt der Mensch, fragt die App über den Host den Server, und die Anzeige ändert sich, ganz ohne LLM. Das ist schneller, kostet keine Tokens und ist vorhersagbar. Damit das LLM trotzdem weiß, was der Mensch gerade sieht, schickt die App ihm mit updateModelContext still eine Notiz.

Und wenn der Host keine MCP Apps kann? Dann bekommt das LLM die Daten trotzdem als Text und antwortet ganz normal. Eine MCP-App muss deshalb immer auch ohne Oberfläche sinnvoll funktionieren. Genau das siehst du im Terminal in Station 4: Dort bist du ein Client ohne Oberfläche.

Aufträge zu MCP Apps (im Terminal, Station 4)
  1. Schicke tools/list. Welche Tools haben eine Oberfläche? Woran erkennst du das?
  2. Rufe notenuebersicht für die 7a in Mathematik auf (Vorlage „MCP App: …“). Was bekommst du, was würde ein Host mit MCP Apps zusätzlich tun?
  3. Hole die Oberfläche mit resources/list und resources/read. Welcher MIME-Typ steht dabei? Von welcher Adresse darf die Seite Skripte laden?
  4. Rufe note_vorschlagen auf. Wurde dabei schon eine Note eingetragen? Was passiert bei einem Nachnamen, den es zweimal gibt?
